# Redis 分布式锁原理简述

## 核心加锁机制
Redis 分布式锁利用其单线程执行模型与原子命令实现跨进程/节点的互斥访问[4]。基础方案采用 `SET key value NX EX` 命令，确保“键不存在时赋值并附带过期时间”的原子操作，有效防止客户端异常崩溃导致的永久死锁[8]。

## 安全解锁与原子性
加锁时需绑定唯一标识（如 UUID）。解锁必须严格校验标识归属，避免误删其他客户端持有的锁。因“校验+删除”涉及多步操作，需借助 Lua 脚本在 Redis 服务端原子执行，保障释放过程的绝对安全[5]。

## 缺陷与看门狗续期
原生方案缺乏可重入性与自动续期能力，固定 TTL 易导致长耗时业务提前释放锁，引发并发冲突[10]。Redisson 等工业级框架通过 Hash 结构实现可重入锁，并内置“看门狗（Watchdog）”机制[2]。若未显式指定租约时间，看门狗后台线程默认每 10 秒检测一次，若客户端仍活跃则自动将锁有效期重置为 30 秒，彻底解决业务超时导致的锁失效问题[8]。

## 高可用保障
针对 Redis 主从异步复制可能引发的锁丢失问题，Redis 官方提出 Redlock 算法。该算法要求客户端在多数独立 Redis 实例上并行加锁成功，以多数派共识机制提升分布式架构下的容错率与数据安全性[13]。
