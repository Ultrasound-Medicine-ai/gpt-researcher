# 向量数据库在 RAG 中的选型对比（Milvus / pgvector / Qdrant）

## 概述

向量数据库在检索增强生成（RAG）系统中扮演着至关重要的角色，它们负责存储和高效检索外部知识，使得大型语言模型（LLMs）能够基于最新的、领域特定的信息生成更准确、更具上下文相关性的答案。本文将详细对比 Milvus、pgvector 和 Qdrant 三种向量数据库，并给出各自的适用场景。

## 核心特性与架构

### Milvus

- **开源协议**：Apache-2.0
- **主要语言**：Go, C++
- **核心特点**：
  - 专为大规模向量搜索优化
  - 支持多种索引类型和搜索算法
  - 提供分布式架构
  - 支持多种相似性度量方式
- **部署方式**：云/Docker/Kubernetes
- **混合搜索**：支持
- **适用场景**：大规模 AI 应用 [4]

### pgvector

- **开源协议**：PostgreSQL License（类似 MIT）
- **主要语言**：C
- **核心特点**：
  - PostgreSQL 的扩展
  - 为 PostgreSQL 增加向量相似性搜索功能
  - 支持多种向量数据类型和距离度量
  - 继承 PostgreSQL 的 ACID 特性
- **部署方式**：任何 PostgreSQL 环境
- **混合搜索**：支持
- **适用场景**：PostgreSQL 用户 [3]

### Qdrant

- **开源协议**：Apache-2.0
- **主要语言**：Rust
- **核心特点**：
  - 高性能、大规模的向量相似性搜索引擎
  - 支持稠密向量和稀疏向量
  - 提供 RESTful API 和 gRPC API
  - 与 LangChain、LlamaIndex 等框架深度集成
- **部署方式**：云/Docker
- **混合搜索**：支持
- **适用场景**：大规模向量搜索 [4]

## 性能与扩展性

### 性能基准测试

根据 VectorDBBench 的测试结果 [13]，Qdrant 和 Weaviate 在 HNSW 索引下表现优异，具有高 QPS 和高召回率。Milvus 在大规模数据（>1亿）下优势明显，得益于其分层存储与计算分离架构 [14]。

- **Qdrant**：在过滤查询方面表现出色，适合需要复杂过滤条件的场景。
- **Milvus**：在处理超大规模数据时表现出色，支持 PB 级向量数据和千亿级别向量检索 [9]。
- **pgvector**：性能中等，适合对延迟要求不苛刻的 OLTP 场景 [14]。

### 扩展性

- **Milvus**：天生为分布式设计，支持水平扩展，适合超大规模（十亿级向量）的应用 [9]。
- **Qdrant**：支持分片和副本，可集群部署，但扩展复杂度低于 Milvus [14]。
- **pgvector**：更适合中小规模场景（千万级以下），扩展性有限 [14]。

## 生态集成与易用性

### 生态集成

- **Milvus**：原生支持多种 LLM 开发生态（如 LangChain、LlamaIndex），并提供 Towhee 等数据处理工具链 [14]。
- **Qdrant**：提供原生 LLM 插件（如 auto-schema、RAG 模板），与 LangChain 和 LlamaIndex 兼容良好 [14]。
- **pgvector**：作为 PostgreSQL 的扩展，可以复用现有的 PostgreSQL 生态，支持 SQL 查询+向量检索混合 [6]。

### 易用性

- **Milvus**：虽然功能强大，但运维复杂度较高，需要 Kubernetes 等容器编排平台 [9]。
- **Qdrant**：安装简单，代码量少，零配置启动，适合快速原型开发和小规模生产环境 [6]。
- **pgvector**：对于熟悉 PostgreSQL 的开发者来说，使用起来非常自然，不需要引入新的组件 [6]。
