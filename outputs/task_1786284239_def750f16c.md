# 向量数据库在 RAG 中的选型对比（Milvus / pgvector / Qdrant）

## 概述

向量数据库在检索增强生成（RAG）系统中扮演着至关重要的角色，它们负责存储和高效检索外部知识，使得大型语言模型（LLMs）能够基于最新的、领域特定的信息生成更准确、更具上下文相关性的答案。本文将详细对比 Milvus、pgvector 和 Qdrant 三种向量数据库，并给出各自的适用场景。

## 1. Milvus

### 1.1 核心特性
- **开源**：Apache 2.0 许可证 [1]
- **支持多种索引类型**：HNSW、IVF_FLAT、IVF_SQ8、IVF_PQ、SCANN 等 [9]
- **分布式架构**：支持水平扩展，适合超大规模数据集 [1][4][6]
- **高可用性**：支持多副本和故障恢复 [1][4]

### 1.2 性能
- **延迟**：单查询 <100ms，在高并发和大规模数据集（亿级向量）场景下表现优异 [12]
- **吞吐量**：2000万768维向量（HNSW索引），单机可达100-500 QPS [12]
- **召回率**：性能领先，支持多种索引类型以平衡速度和精度 [12]

### 1.3 适用场景
- **超大规模数据平台**：适用于需要处理十亿级向量的企业级应用 [1][4][6]
- **高性能要求**：对延迟和吞吐量有严格要求的生产环境 [1][4][6]
- **复杂过滤需求**：支持高效的标量过滤（布尔、范围、IN 查询等），且可与向量检索联合优化 [9]

## 2. pgvector

### 2.1 核心特性
- **开源**：PostgreSQL 扩展，遵循 PostgreSQL 许可证 [3]
- **SQL 兼容**：支持 SQL 查询和向量检索混合 [3][4][6]
- **部署方式**：任何 PostgreSQL 环境 [3][4][6]

### 2.2 性能
- **延迟**：P99 延迟约为 100-300ms [4]
- **吞吐量**：适中，适合中小规模数据集 [4][6]
- **最大规模**：受 PostgreSQL 限制，通常为千万级以下 [4][6]

### 2.3 适用场景
- **已有 PostgreSQL 生态**：避免引入新组件，适合已有 PostgreSQL 基础设施的团队 [4][6]
- **中小规模数据集**：适用于百万至千万级向量的数据集 [4][6]
- **SQL 开发者友好**：对熟悉 SQL 的开发者非常友好 [4][6]

## 3. Qdrant

### 3.1 核心特性
- **开源**：Apache 2.0 许可证 [1]
- **高性能**：Rust 实现，资源利用率高，延迟低 [1][4][6]
- **功能全面**：支持过滤、多向量、集合等高级功能 [1][4][6]
- **分布式支持**：支持分片和副本，可集群部署 [1][4][6]

### 3.2 性能
- **延迟**：单查询 <100ms，2000万向量约100-400 QPS [12]
- **吞吐量**：单机稍弱，分布式提升有限 [12]
- **召回率**：性能稳定，支持 HNSW 和量化（如 PQ） [9]

### 3.3 适用场景
- **中等规模生产环境**：适用于 10 万到 1000 万级向量的数据集 [4][6]
- **低延迟高吞吐应用**：对延迟和吞吐量有较高要求的应用 [4][6]
- **稀疏向量支持**：自 v1.7 起支持稀疏向量 [9]

## 4. 对比总结

### 4.1 功能对比
| 特性 | Milvus | pgvector | Qdrant |
| --- | --- | --- | --- |
| 开源 | 是 | 是 | 是 |
| 索引类型 | 多种 | IVFFlat, HNSW | HNSW, 量化 |
| 分布式支持 | 支持 | 不支持 | 支持 |
| 过滤支持 | 高效 | 强大 | 高效 |

### 4.2 性能对比
| 特性 | Milvus | pgvector | Qdrant |
| --- | --- | --- | --- |
| 延迟 (P99) | <100ms | 100-300ms
