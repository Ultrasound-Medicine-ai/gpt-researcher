# Redis 详细研究报告

## 一、基本定义与核心特性

Redis（Remote Dictionary Server）是一个开源、遵守 BSD 协议的内存键值数据库，以高性能、低延迟著称，广泛应用于缓存、消息队列、会话存储、实时排行榜等场景[1]。其数据默认驻留于内存，支持每秒数十万次读写操作，典型延迟为微秒至毫秒级[2]。所有操作均为原子性执行，确保高并发下数据一致性与完整性[1]。

Redis 不仅提供基础键值存储，更内置丰富数据结构：字符串（String）、哈希（Hash）、列表（List）、集合（Set）、有序集合（Sorted Set）、HyperLogLog、GEO、Stream 等，显著拓展了适用边界[1][2]。此外，它原生支持发布/订阅（Pub/Sub）模型、Lua 脚本、事务处理及管道（Pipeline）技术，强化了复杂业务逻辑表达能力[1][2]。

## 二、架构与运行机制

Redis 采用单线程事件驱动模型处理客户端请求，通过非阻塞 I/O 和高效数据结构（如跳表、压缩列表、哈希表）实现极致性能；该设计规避了多线程锁竞争开销，同时简化了并发控制逻辑[1]。尽管单线程，其吞吐能力在主流硬件上仍可达 10–100 万 QPS（依操作类型与配置而异）[1]。

持久化方面，Redis 提供两种互补机制：RDB（快照）与 AOF（追加日志）。RDB 适合灾难恢复与备份，AOF 则提供更高数据安全性，支持 `appendfsync` 多级同步策略（如每秒、每次写入或从不）[2]。两者可独立或混合使用，兼顾性能与可靠性[2]。

## 三、高可用与分布式演进

Redis 的演进路径清晰：2009 年由 Salvatore Sanfilippo（antirez）初创，2010–2013 年扩展数据类型与 Pub/Sub、事务等功能；2014–2017 年引入集群（Cluster）与哨兵（Sentinel），实现自动分片与故障转移；2018 年至今，依托 Redis Modules API 支持模块化扩展，并推出企业版，集成高可用、动态分片与安全审计等企业级能力[2]。
