# SSE（Server-Sent Events）技术调研报告

## 技术概述与核心原理
Server-Sent Events（SSE）是一种基于标准 HTTP 协议的服务器推送技术，允许服务端主动向客户端建立单向持久连接并实时推送数据流[4]。其本质并非独立的新协议，而是构建在 HTTP/1.1 或 HTTP/2 之上的标准化扩展用法[6]。客户端通过原生 `EventSource` API 发起 GET 请求，服务端以 `Content-Type: text/event-stream` 响应并保持连接长开，从而彻底摒弃了传统短轮询与长轮询机制[4]。

## 核心特性与协议规范
SSE 采用 UTF-8 纯文本传输，消息体由 `data:`、`event:`、`id:` 和 `retry:` 字段构成，以双换行符分隔[4]。其核心工程优势在于内置断线自动重连机制，并支持通过 `Last-Event-ID` 实现消息续传，显著降低了连接维护与状态同步的开发成本[4]。在 HTTP/1.1 环境下，浏览器存在单域名 6 个并发连接的限制，但升级至 HTTP/2 后可通过多路复用彻底消除该瓶颈[2]。

## 与 WebSocket 的对比分析
| 特性维度 | SSE | WebSocket |
|---|---|---|
| 通信方向 | 单向（服务端→客户端） | 双向全双工 |
| 协议基础 | 标准 HTTP | 独立协议（需 HTTP 升级握手） |
| 重连机制 | 浏览器内置自动重连 | 需开发者手动实现 |
| 数据格式 | 仅支持文本 | 支持文本与二进制 |
| 网络兼容性 | 极佳（无缝兼容代理/CDN/防火墙） | 需额外配置支持 |
*(数据综合自：[1], [2])*

## 典型应用场景与选型建议
SSE 极其适用于服务端主导的实时数据流场景，如 AI 大模型逐字输出（Token Streaming）、系统运维监控、金融行情推送及社交动态通知[4]。若业务仅需服务端向客户端单向广播，SSE 凭借轻量架构、免维护重连及原生 HTTP 兼容性，是比 WebSocket 更优的工程选择[1]。仅在需要客户端高频上行交互（如在线协同编辑、多人游戏、即时聊天）时，才应选用 WebSocket[2]。综合而言，SSE 以极简设计实现了高效的实时推送，是现代 Web 实时通信栈中不可或缺的轻量级方案。
