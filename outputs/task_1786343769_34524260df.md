# Server-Sent Events (SSE) 技术调研报告

## 核心原理与技术特性
Server-Sent Events (SSE) 是一种基于标准 HTTP 协议的服务器推送技术，专为实现高效、轻量级的单向实时通信而设计 [1][2]。其底层机制依赖客户端通过 `EventSource` 对象发起 HTTP GET 请求，服务器以 `Content-Type: text/event-stream` 响应并维持持久连接 [1]。数据采用 UTF-8 文本格式传输，严格遵循 `data:`、`event:` 与 `id:` 字段规范 [1]。SSE 的核心价值在于内置断线自动重连机制，并支持通过 `Last-Event-ID` 实现消息续传，有效保障了数据流的连续性与可靠性 [1]。

## 协议对比与架构优势
相较于 WebSocket 的全双工通信与独立协议栈，SSE 仅支持服务器至客户端的单向数据流，完全复用现有 HTTP 基础设施，无需复杂握手，且原生具备自动重连能力，集成复杂度显著更低 [1][6]。与传统长轮询相比，SSE 仅需建立一次连接即可持续推送多事件，彻底消除了高频请求带来的网络开销与服务器负载，在实时性与资源效率上均占据优势 [1]。

| 特性维度 | SSE | WebSocket | 长轮询 |
|---|---|---|---|
| 通信方向 | 单向（服务器→客户端） | 双向（全双工） | 单向（请求-响应） |
| 协议基础 | 标准 HTTP | 独立 WebSocket 协议 | 标准 HTTP |
| 数据格式 | 文本（UTF-8） | 文本或二进制 | 文本/JSON |
| 重连机制 | 内置自动重连与续传 | 需手动实现 | 依赖客户端循环重试 |

## 典型场景与工程实践
SSE 高度契合服务器驱动型数据流场景。在 AI 大语言模型应用中，SSE 被广泛用于 Token 级流式输出，有效缓解用户等待焦虑并提升交互体验 [1][6]。同时，金融行情推送、服务器性能监控、赛事直播及在线协同工具的状态同步，均依赖 SSE 实现低延迟更新 [1]。工程部署时需注意，现代主流浏览器已原生支持 `EventSource`，但 IE 环境需引入 Polyfill 降级至长轮询 [1]；此外，跨域请求受 CORS 策略严格约束，服务端需正确配置跨域响应头 [1]。

## 调研结论
综合技术特性与生态现状，SSE 是构建单向实时数据流的最优解。其基于 HTTP 的轻量架构、开箱即用的重连机制及极低的运维成本，使其在 AI 流式交互、实时通知与监控领域具备不可替代性。对于无需客户端高频回传数据的业务，SSE 在开发效率、网络兼容性与资源消耗上均优于 WebSocket，建议作为单向推送场景的首选技术栈 [1][6]。
