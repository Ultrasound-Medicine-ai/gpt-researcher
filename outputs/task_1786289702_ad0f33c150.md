# Redis 分布式锁原理简述

Redis 分布式锁利用 Redis 的单线程模型和原子操作特性，在分布式环境下协调多进程对共享资源的互斥访问，是保障数据一致性的重要机制 [1]。

## 基础实现原理

早期实现常使用 `SETNX` 命令配合 `EXPIRE` 设置过期时间，但两者非原子操作，若进程在 `SETNX` 成功后崩溃，将导致死锁 [1][3]。自 Redis 2.6.12 版本起，官方推荐使用 `SET key unique_value NX PX timeout` 命令，该命令能原子性地完成“加锁”与“设置过期时间” [4][13]。解锁时，必须先判断锁的归属（value 值），再执行删除。为防止并发情况下的误删，必须使用 Lua 脚本保证“判断”与“删除”操作的原子性 [8][9]。

## 核心挑战与优化

**锁超时问题**：若业务执行时间超过锁的过期时间，锁会自动释放，引发并发冲突。解决方案是引入“看门狗”机制，如 Redisson 框架，通过后台线程自动为锁续期 [5][7]。

**集群可靠性**：在普通主从模式下，因数据异步复制，主节点宕机可能导致锁丢失。为此，Redis 官方提出了 Redlock 算法 [4]。

## Redlock 算法

Redlock 算法通过向多个（通常为 5 个）独立的 Redis 节点请求加锁。客户端需在大多数（N/2+1）节点上成功加锁，且总耗时小于锁的有效时间，才算加锁成功 [13]。该算法有效解决了单点故障和主从切换时的脑裂问题，保证了高可用环境下的锁安全性 [1][9]。

## 总结

Redis 分布式锁从简单的 SET 命令演进到复杂的 Redlock 算法，核心在于平衡互斥性、防死锁和高可用性。生产环境建议优先使用 Redisson 等成熟框架，以规避原子性缺失和锁过期等风险 [7]。
